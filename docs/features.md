# Features

## 공통 데이터 동기화

- 인증된 앱 세션에서 내 Realtime 채널을 한 번만 구독한다. 화면 이동은 내 채널을 유지하고 필요한 친구 채널만 변경한다.
- 정상 연결의 레이스·친구·미읽은 신호는 60초마다 누락을 보정한다. 연결 장애 시 각각 2초·20초·5초 폴링으로 복귀한다. 레이스는 필요한 친구 채널이 모두 연결돼야 정상으로 판정한다.
- 숨김·오프라인에서 신규 조회를 중단하고 복귀·재연결·KST 자정에 필요한 데이터를 다시 읽는다. 초기 서버 데이터를 즉시 중복 조회하지 않으며 사용자별 캐시를 분리한다.
- 친구 조회와 신호 토스트는 앱 전체에서 하나로 공유한다. 정산 완료·날짜 변경은 이전 캐시보다 우선하고, 같은 날의 낙관적 탭은 오래된 조회로 되돌리지 않는다.
- 신호의 브로드캐스트 성공은 읽음으로 간주하지 않는다. 보이는 화면에서 수신한 클라이언트가 인증된 수신 확인을 보내며, 푸시 직전에도 읽지 않은 신호만 발송한다. 같은 ID의 인앱 토스트는 10분 동안 중복 표시하지 않는다.
- 수용 기준: 정상 연결·전경 idle 5분 동안 세 GET 합계 15회 이하(초기 연결·이벤트 제외), 친구 이동 1초 이내, 숨김 중 신규 GET 0회. 조회 감소와 실기기 푸시는 각각 검증한다.

각 기능은 F 번호로 참조한다. 구현 시 해당 항목의 수용 기준을 완료 조건으로 삼는다.

## F0 계정과 친구 등록

**F0-1 아이디 로그인**

- 이메일 없이 **아이디 + 비밀번호** 로 가입·로그인한다. 아이디는 영문 소문자·숫자·`_`, 3~20자. 대문자로 입력해도 소문자로 저장한다.
- 가입 시 닉네임(1~12자)을 받는다. 레이스·랭킹·신호 문구에는 닉네임을, 검색에는 아이디를 쓴다.
- 로그인·가입이 실패하면 **왜 실패했는지** 구분해서 알려준다. 그냥 "실패했어요" 로 뭉뚱그리지 않는다.
  - 아이디·비밀번호 불일치 → "아이디 또는 비밀번호가 틀렸어요". 없는 아이디와 틀린 비밀번호를 **구분하지 않는다** — better-auth 가 두 경우에 같은 코드(`INVALID_USERNAME_OR_PASSWORD`)와 같은 응답 시간을 주도록 일부러 맞춰 놨고(없는 아이디여도 더미 해시를 돌린다), 이를 구분하려면 "이 아이디 있나요" 를 답해주는 엔드포인트가 따로 필요하다. 그건 F0-2 의 아이디 검색과 합쳐져 계정 목록을 훑을 수 있는 통로가 된다.
  - 형식 오류(너무 짧은·긴·잘못된 아이디) → 어느 칸이 왜 틀렸는지 그 칸 아래에 쓴다.
  - 네트워크 끊김 → "인터넷 연결을 확인해 주세요".
  - 서버 오류(5xx) → "잠시 후 다시 시도해 주세요".
  - 시도 초과(429) → "잠시 뒤에 다시 시도해 주세요".
- 실패해도 버튼은 항상 원래 상태로 돌아온다. 요청이 예외를 던져도 "들어가는 중…" 에서 멈추지 않는다.
- 수용 기준: 가입 즉시 로그인 상태로 `/` 에 진입한다. 중복 아이디는 "이미 쓰는 아이디예요" 로 거절한다. 서버를 끈 채로 로그인하면 "인터넷 연결을 확인해 주세요" 가 뜨고 버튼을 다시 누를 수 있다.

**F0-2 친구 요청 (아이디 검색)**

- `/friends` 에서 상대 아이디를 정확히 입력해 검색하고 "친구 요청" 을 누르면 `pending` 요청이 생긴다. 상대가 수락하기 전에는 친구가 아니고 레이스·신호에도 보이지 않는다 (2026-09-19 변경: 즉시 등록은 모르는 사람이 일방적으로 내 레이스에 들어오는 문제가 있었다).
- 내 아이디를 화면 상단에 보여줘 상대가 검색할 수 있게 한다.
- "보낸 요청" 목록에 대기 중인 요청을 보여주고 취소할 수 있다.
- 본인·이미 친구·이미 요청함·없는 아이디·차단한(당한) 상대는 각각 안내 문구로 거절한다.
- 상대가 나에게 이미 요청을 보낸 상태에서 내가 같은 상대에게 요청하면 새 요청을 만들지 않고 그 요청을 수락 처리한다.
- 수용 기준: A 가 B 에게 요청해도 수락 전에는 서로의 레이스 화면에 보이지 않는다.

**F0-3 친구 요청 수락·거절**

- 받은 요청은 `/friends` 의 "받은 요청" 목록에 보이고, 각 줄에서 수락·거절한다.
- 대기 중인 요청이 있으면 앱 진입 시 다이얼로그로 한 건씩 띄워 수락·거절을 받는다. 닫으면 목록에서 계속 처리할 수 있다.
- 수락하면 그 순간부터 양방향 친구다 — A·B 모두의 레이스 화면에 서로가 보인다.
- 거절하면 요청 row 를 지운다. 상대에게 거절 사실을 알리지 않고, 상대는 다시 요청할 수 있다.
- 요청 도착·수락은 Supabase Realtime 으로 상대 채널에 전달해 새로고침 없이 반영한다 (`friend` 이벤트). 전달 실패해도 폴링이 받쳐준다.
- 수용 기준: 두 브라우저에서 A 가 요청하면 B 화면에 새로고침 없이 다이얼로그가 뜨고, B 가 수락하면 A 의 친구 목록에 B 가 나타난다.

**F0-4 친구 삭제·차단**

- 친구 목록의 각 줄에서 "삭제" 하면 friendship row 를 지운다. 양쪽 목록에서 즉시 사라지고, 나중에 다시 요청할 수 있다.
- "차단" 하면 row 를 `blocked` 로 바꾸고 누가 차단했는지(`blockedById`)를 기록한다. 차단한 상대는 검색에 나오지 않고 요청도 보낼 수 없다 (양쪽 모두).
- 차단 목록은 `/friends` 하단의 "차단한 사람" 섹션에서 보고 해제할 수 있다. 해제 권한은 차단한 사람에게만 있고, 해제하면 row 를 지워 친구가 아닌 상태로 돌린다.
- 삭제·차단은 되돌릴 수 없으므로 확인 다이얼로그를 거친다.
- 수용 기준: A 가 B 를 삭제하면 양쪽 레이스 화면에서 서로가 사라진다. A 가 B 를 차단하면 B 는 A 를 검색할 수 없다.

**F0-5 로그아웃**

- `/my`(마이페이지) 메뉴 목록의 맨 아래에 로그아웃 줄을 둔다. 상단에 닉네임과 `@아이디` 가 이미 보이므로 "누구로 로그인 중" 을 따로 적지 않는다.
- 누르면 확인 다이얼로그를 거친 뒤 세션을 지우고 `/login` 으로 보낸다. 되돌릴 수 없는 동작은 아니지만 연타 중 잘못 누르면 레이스가 끊긴다.
- 로그아웃 후에는 뒤로 가기로 앱 화면에 돌아올 수 없다 — 서버 레이아웃이 세션을 다시 확인해 `/login` 으로 돌린다.
- 수용 기준: 로그아웃하면 `/login` 으로 이동하고, 뒤로 가기를 눌러도 `/` 로 들어가지 못한다.

**F0-6 운영 도메인 전환**

- 운영 주소는 `https://taptohome.site`다. 기존 `tap-to-home-web.vercel.app`으로 접속하면 경로와 쿼리를 유지해 새 주소로 이동한다.
- 기존 Android·iOS 웹뷰 앱은 시작 주소를 유지한 채 서버 리다이렉트를 따라간다. 도메인 전환 후 기존 사용자는 새 주소에서 다시 로그인한다.
- `/api/cron` 및 하위 경로는 이동시키지 않는다. Preview 배포 주소와 로컬 주소도 그대로 유지한다.
- 수용 기준: 기존 주소의 루트·로그인·기록 링크가 새 HTTPS 주소로 이동하고, 새 주소의 로그인과 세션 조회가 정상 동작한다. 기존 주소의 정산 요청은 인증 검사에 직접 도달한다.

## F1 퇴근 레이스 (메인)

**F1-1 버튼 연타 및 이동**

- "퇴근하고 싶다" 버튼을 누를 때마다 오늘의 누적 횟수 +1.
- 누적 횟수에 따라 졸라맨이 단계별로 전진한다. 단계와 임계값(2026-09-19 조정: 집까지 100 → 300 → 10000, 300 도 몇 분이면 끝나 하루 종일 누를 대상이 못 됐다. 2026-09-21 조정: 10000 → 5000, 하루 안에 집까지 닿는 사람이 너무 적었다). 간격은 뒤로 갈수록 벌어져 막판이 제일 길다:

| 단계 | 위치 | 누적 횟수 |
| --- | --- | --- |
| 0 | 자리 | 0 |
| 1 | 엘리베이터 | 750 |
| 2 | 로비 | 1600 |
| 3 | 횡단보도 | 2500 |
| 4 | 지하철 | 3650 |
| 5 | 집 | 5000 |

- 각 단계는 경로 위에 손그림 랜드마크(책상·엘리베이터 문·로비 입구·횡단보도·전동차·집)로 표시한다. 졸라맨과 같은 연필 선이며, 지나온 곳은 진하게, 아직 못 간 곳은 연하게 그린다.
- 책상·엘베·로비·신호등·지하철·집은 **기존 레일 위에 각각 한 번만 고정**한다. 캐릭터와 별도 장면을 레일 위쪽에 띄우거나, 캐릭터를 따라 가구·건물이 이동하지 않는다.
- 마지막 횟수 증가 후 800ms 동안 캐릭터만 레일을 따라 다음 요소 방향으로 달린다. 추가 탭이 없으면 도달한 구간의 고정 요소 안에서 대기한다. 누적 횟수와 레일의 진행 표시점은 유지한다. 메인 진행 바와 랭킹 레인(친구의 실시간 횟수 증가 포함)에 동일하게 적용한다.
  - 달리기 두 프레임은 일정한 박자로 교대하며, 연타가 보행 주기를 뒤집거나 다시 시작하지 않는다. 대기·출발 사이에 캐릭터 크기가 바뀌지 않고, 첫 출발 위치도 대기 위치에서 이어진다. 문 선과 지하철 손잡이를 잡는 팔은 얼굴을 가리지 않는다.
  - 자리: 책상 앞 의자에 앉아 있다가 탭하면 일어나 달린다. 등받이와 엉덩이에 닿는 좌판을 그린다.
  - 엘리베이터: 안에 서 있다가 탭하면 문이 열리고 달려 나온다.
  - 로비: 유리문 안에 있다가 탭하면 문이 열리고 달려 나온다.
  - 횡단보도: 신호등 앞에 서서 기다리다가 탭하면 보행 신호로 바뀌고 달린다. 왼쪽에서 오른쪽으로 대기 위치→신호등→횡단보도 순서로 배치해 2,500회 도착 전에 캐릭터나 진행 표시점이 신호등을 지나지 않게 한다. 작은 화면에서도 구분되도록 켜진 불의 위치와 `대기`/`건너기` 표시를 함께 쓴다.
  - 지하철: 전동차 안에서 손잡이를 잡고 있다가 탭하면 문이 열리고 달려 나온다.
  - 집: 5,000회에 도착하면 침대에 눕는다. 더 이상 달리기 상태로 바뀌지 않는다.
    - 누운 자세는 홍보 릴스 버전 2와 동일하게 머리 오른쪽 가장자리에 몸통을 연결하고, 팔·다리는 머리 바깥에 둔다. 감은 눈은 머리 중심에서 −90도 회전한다. 메인·랭킹·칭호·기록의 공용 포즈 두 프레임에 적용하며, 침대와 수면 표시가 얼굴·지붕에 겹치지 않게 한다.
- 하루 탭은 **5,000회까지만** 받는다. 도착 즉시 버튼을 완료 상태로 표시하고, 추가로 누르거나 키보드로 실행하려 하면 `이미 퇴근했습니다`를 안내한다. 추가 시도는 카운트·탭 이벤트·연타 신호에 포함하지 않는다.
- 버튼의 눌림 표시는 손을 떼거나 취소하거나 키보드 포커스가 이동하면 해제된다. 기기의 동작 줄이기 설정에서는 반복 애니메이션 없이 한 포즈로 반응한다.
- 서버도 같은 한도를 적용한다. 마지막 배치가 한도를 넘으면 남은 횟수만 저장하고, 여러 기기에서 동시에 보내도 5,000회를 넘지 않는다. 이미 도착한 요청은 현재 횟수를 반환하며 추가 이벤트나 마지막 탭 시각을 기록하지 않는다. 기존에 한도를 넘긴 기록은 보존하되 추가 탭을 막는다.
- 수용 기준: 탭 즉시(100ms 이내) 카운트와 캐릭터가 반응한다. 새로고침 후에도 오늘 횟수가 유지된다. 각 구간의 대기→달리기→대기와 4,999→5,000회→추가 시도 차단을 확인한다. 다음 날에는 다시 0회부터 누를 수 있다.
- 개발용 `/dev/ui#race-scenes` 에서 여섯 구간의 SVG를 확대해 보고, 구간별 출발을 한 번 재생하거나 전체를 반복 재생한다. 실제 `RaceScene`·메인 진행 바·랭킹 레인을 함께 사용해 800ms 후 대기로 돌아오는 모습과 집의 누운 상태를 확인한다. 미리보기는 서버에 탭을 저장하지 않는다.

**F1-2 실시간 대결 구도**

- 전체 랭킹은 `/ranking` 탭에서 본다. 메인 `/` 는 내 진행도와 탭 버튼 사이에 **나를 제외한 친구 중 상위 2명**의 레인을 표시하고, 전체 랭킹으로 가는 링크를 유지한다.
- 메인 친구 레인은 랭킹의 정렬 순서를 따르며 닉네임·전체 순위(나 포함)·누적 횟수·진행 위치를 보여준다. 친구가 1명이면 1명만 표시하고, 없으면 레인 영역을 숨기고 기존 친구 등록 안내를 유지한다.
- 메인 친구 TOP2 레일은 사용자별 표시 설정을 따른다. 기본은 켜짐이며 `/my`에서 끄면 메인의 친구 레일 영역을 숨긴다. 내 진행도·탭 버튼·전체 랭킹 링크와 `/ranking`의 친구 레인은 그대로 유지한다.
- `/ranking` 최상단에 내 레인을 고정하고, 그 아래 친구 레인만 스크롤한다. 친구가 몇 명이든 내 순위는 화면에 남는다.
- 친구들의 졸라맨이 같은 줄노트 경로 위에 표시된다. 예: `민경 273회 🚶 집 앞`, `수현 231회 🚇 지하철`.
- 친구가 탭하면 1초 이내에 메인과 랭킹 화면의 친구 캐릭터가 움직인다. 두 화면 모두 같은 실시간 구독을 쓰며, 순위가 바뀌면 메인 상위 2명도 갱신한다.
- 랭킹은 횟수 내림차순이다.
- 수용 기준: 표시 설정이 켜져 있으면 메인에서 내 진행도와 버튼 사이에 본인을 제외한 상위 친구가 최대 2명 보이고, 내 순위와 관계없이 친구 2명을 선택한다. 두 브라우저에서 메인·`/ranking` 의 친구 이동과 순위 변경이 반영된다. 친구 목록을 끝까지 스크롤해도 랭킹의 내 레인이 상단에 남는다.

## F2 퇴근 신호 (친구 기능, 버튼 메시징)

- 텍스트 채팅 없음. 연타 횟수와 속도를 감지해 친구에게 상태 알림을 보낸다.
- 연타 판정 창: 마지막 탭에서 1.5초 이내 연속 탭을 하나의 연타로 묶는다 (초안).

| 연타 | 신호 | 알림 문구 예 |
| --- | --- | --- |
| 1회 | 일반 신호 | 수현이도 퇴근하고 싶어 합니다 |
| 5회 | 강한 신호 | 수현이 강하게 퇴근하고 싶어 합니다 |
| 10회 | 긴급 퇴근 신호 | 민지가 긴급 퇴근 신호를 보냈습니다 |
| 30회 | 구조 요청 | 민지가 구조 요청을 보냈습니다 |

- 한 연타 묶음에서는 도달한 최고 등급 하나만 발송한다 (5회 → 10회로 넘어가면 10회 알림만).
- 같은 등급 알림은 같은 상대에게 10분에 한 번으로 제한한다 (스팸 방지, 초안).
- 전달 채널: 인앱 토스트(실시간) → 네이티브 푸시(백그라운드) 순으로 구현. 웹 푸시(VAPID)는 iOS 웹뷰에서 동작하지 않아 쓰지 않는다 (`docs/decisions/0006-native-push-fcm.md`).
- 수용 기준: 10회 연타 시 상대 화면에 긴급 신호 토스트가 뜬다.

**F2-1 백그라운드 푸시 (ADR 0006)**

- 앱을 닫은 상태에서도 퇴근 신호가 알림으로 도착한다.
- 앱 실행 시 FCM 토큰을 받아 `TapToHome` JS 채널로 웹에 넘기고, 웹이 `POST /api/push/tokens` 로 저장한다.
- 이미 인앱으로 읽은 신호(`readAt` 이 채워진 신호)는 푸시하지 않는다.
- 알림 문구는 인앱 토스트와 같은 카피(`src/features/signal/messages.ts`)를 쓴다.
- 수용 기준: 앱을 종료한 상태에서 친구가 10회 연타하면 잠금 화면에 긴급 신호 알림이 뜬다.

## F3 하루 결과 (퇴근 도감 및 칭호)

**F3-1 행동 패턴 분석 칭호**

하루 동안의 탭 시각과 빈도를 분석해 일일 칭호를 부여한다. 횟수 기준은 F1-1 임계값과 같은 스케일로 유지한다(2026-09-21 집 5000번에 맞춰 조정). 초기 칭호 규칙(확장 가능, 목표 50개):

| 칭호 | 조건 |
| --- | --- |
| 출근하자마자 집 가고 싶었던 자 | 첫 탭이 09:30 이전 |
| 점심 먹고 모든 의욕을 잃은 자 | 13시 이후 탭이 전체의 60% 이상 |
| 퇴근 1시간 전 폭주형 | 17시 이후 탭 1500회 이상 |
| 마음만 이미 집에 있음 | 하루 5000회 이상 (= 레이스 집 도착) |
| 오늘은 버틸 만했던 자 | 하루 500회 미만 |

- 조건이 여러 개 맞으면 모두 부여한다. 대표 칭호 하나는 우선순위 규칙으로 정한다.
- 판정 시각: 하루 종료(KST 자정) 배치. 사용자가 직접 누르는 "오늘 정산" 은 없앴다 (ADR 0008).

**F3-2 도감 수집**

- 획득한 칭호가 도감에 누적된다. 예: `14/50`.
- 미획득 칭호는 실루엣과 힌트만 보여준다.
- 수용 기준: 정산 후 도감 카운트가 올라가고, 새 칭호에 "NEW" 표시가 붙는다.

## F3-3 자동 정산과 기록 보기

- 매일 KST 00:05로 크론을 예약해 어제의 정산을 돌린다. 현재 Vercel Hobby는 시간 단위 스케줄 정확도만 제공하므로 00시대 실행이며 정확히 00:05를 보장하지 않는다. 대상은 어제 탭이 **1회 이상** 있는 유저뿐이다 — 누르지 않은 날은 정산도 알림도 없다 (ADR 0008).
- 정산되면 알림이 간다. 문구는 대표 칭호 기준(`오늘 당신은 '마음만 이미 집에 있음'`), 칭호가 없으면 횟수(`어제 1,204번 퇴근하고 싶었어요`). 탭하면 그날의 기록 상세를 연다.
- 알림을 못 받는 경로(브라우저 접속, 알림 거부)를 위해, 아직 보지 않은 정산 결과가 있으면 앱 진입 시 다이얼로그로 한 번 띄운다. 여러 건이 쌓였으면 가장 최근 한 건만 보여주고 나머지는 함께 본 것으로 처리한다.
- 기록은 레이스 화면의 "기록 보기" 로 들어가는 `/records` 에서 본다. 탭이 아니다. 맨 위에 오늘 진행 상황, 아래에 정산된 날들이 최신순으로 쌓인다 (최근 30일).
- `/records/<날짜>` 는 그날의 총 횟수·첫 탭 시각·랭킹·획득 칭호를 보여준다. 예: `오늘 당신은 마음만 먼저 퇴근한 자 / 총 103회 / 첫 퇴근 욕구 09:32 / 오늘 랭킹 2위`.
- 수용 기준: 탭 0회인 유저에게는 알림이 오지 않는다. 자정을 넘긴 뒤 앱을 열면 어제 결과가 한 번 뜨고, 닫으면 다시 뜨지 않는다.

## F4 마이페이지

- 하단 탭은 레이스·랭킹·친구·마이 4개다. 도감은 `/my/collection` 으로, 정산 결과는 `/records` 로 옮겼다.
- `/my` 허브는 닉네임과 `@아이디` 아래에 내 정보·도감·이용약관·개인정보 처리방침·로그아웃 줄을 둔다. 도감 줄에는 획득 수(`14/50`)를 함께 보여준다. 계정 탈퇴는 맨 아래에 한 단 낮춰 둔다.
- `/my`의 도감 아래에 `친구 TOP2 레일 표시` 켜기/끄기 토글을 둔다. 변경 즉시 로그인한 계정에 저장하며 저장 중에는 중복 변경을 막는다. 실패하면 이전 상태로 복원하고 재시도 안내를 표시한다.
- 표시 설정은 기존·신규 사용자 모두 기본 켜짐이다. 메인으로 돌아오면 바로 반영되고, 새로고침·재로그인·다른 기기에서도 계정에 저장된 값을 읽는다. 다른 사용자의 설정에는 영향을 주지 않는다.
- `/my/profile` 에서 닉네임(1~12자)과 비밀번호를 바꾸고, 알림 두 가지(퇴근 신호·정산 결과)를 켜고 끈다. 아이디는 친구 검색 키라 바꿀 수 없다.
- 알림 설정은 **푸시에만** 적용한다. 인앱 토스트와 진입 다이얼로그는 앱을 직접 열었을 때의 화면이라 설정과 무관하다.
- `/my/delete` 는 사라지는 것을 먼저 알리고, 자기 아이디를 정확히 입력해야 버튼이 열린다. 탈퇴는 소프트 삭제다 — 로그인이 막히고 친구 목록·랭킹·검색에서 사라지며, 같은 아이디로 재가입할 수 없다.
- 수용 기준: 탈퇴한 계정은 친구 검색에 나오지 않고 상대의 랭킹에서도 사라진다. 로그아웃 후 뒤로 가기로 앱 화면에 돌아올 수 없다.
- 표시 설정 수용 기준: 친구가 있는 A가 토글을 끈 뒤 메인으로 돌아오거나 새로고침하면 친구 TOP2 레일이 숨겨지고, 다시 켜면 나타난다. 같은 기기의 B 계정은 자신의 설정을 유지하며, 저장 실패 시 A의 토글과 저장 값은 이전 상태를 유지한다.

## F5 관리자·운영 분석

2026-09-20 승인된 확장 기능. 상세 정의와 와이어프레임은 [관리자 대시보드 설계](superpowers/specs/2026-09-20-admin-dashboard-design.md)를 기준으로 한다. 로그인·초기 계정 설정은 [배포 문서](deploy.md)의 관리자 절차를 따른다.

**F5-1 관리자 전용 접근**

- 관리자 화면은 `/admin`, 전용 로그인은 `/admin/login`이다. 일반 서비스의 화면·로그인·회원가입과 분리한다. 관리자 로그인 페이지는 보호 레이아웃 밖에 둔다.
- 일반 `User`와 별도 저장소의 마스터 계정 1개를 사용한다. 인증 API·인스턴스·세션·쿠키·비밀키를 분리하고 일반 회원을 관리자 권한으로 승격하지 않는다(ADR 0010).
- 초기 마스터 생성·비밀번호 교체·복구는 서버 전용 절차로 수행한다. 공개 관리자 회원가입·초기화 API는 제공하지 않는다.
- `/admin`과 각 보호 API·조치에서 유효한 관리자 세션과 마스터 상태를 확인한다. 일반 세션만 있으면 관리자 페이지는 `/admin/login`으로, 보호 API는 401로 처리한다.
- 수용 기준: 로그인 화면의 리다이렉트 루프와 일반·관리자 간 세션 혼용이 없다. 한쪽 로그아웃은 다른 쪽에 영향을 주지 않고, 마스터 비활성화·비밀번호 교체 후 기존 관리자 세션은 거절된다. 마스터는 회원 수·검색·랭킹·분석 대상에 포함되지 않는다.

**F5-2 전체 사용자 관리**

- 아이디·닉네임·사용자 ID 검색, 계정/활동 상태·가입 기간·친구 유무 필터, 서버 페이지네이션, 사용자 상세를 제공한다.
- 이용 정지·해제·모든 기기 로그아웃을 제공하고 조치자·대상·사유·변경 시각·전후 상태를 기록한다. 정지와 탈퇴를 구분한다.
- 수용 기준: 조치 대상은 일반 `User`에 한정하며 마스터 인증 테이블에는 쓰지 않는다. 감사 이력의 조치자는 `AdminUser`, 대상은 `User`로 구분한다. 정지 상태를 로그인·인증·친구·레이스·신호·푸시·정산에 일관되게 적용하며, 관리자 조회는 사용자 제품 상태를 변경하지 않는다.

**F5-3 운영 대시보드**

- 전체 현황, 접속·재방문, 레이스·소셜 화면을 둔다. 차트는 `react-chartjs-2` + Chart.js 4를 사용한다(ADR 0009).
- 신규 가입·플레이 DAU·완주·구간 도달·정산 누락을 먼저 제공한다. 방문 계측 후 DAU/WAU/MAU·DAU/MAU·D1/D7을 제공한다.
- KST 날짜, 지표의 분자·분모, 데이터 수집 시작일, 집계 시각을 표시한다. 방문과 플레이, 미수집과 0, 관찰 중과 미재방문을 구분한다.
- 수용 기준: 여러 기기·탭의 방문 중복을 제거하고, 주간·월간 방문자는 일별 인원의 합계가 아닌 고유 인원으로 계산한다. 차트 정보를 표로도 읽을 수 있다.

**F5-4 개발 방향 분석**

- 가입 후 첫 탭, 초기 친구 연결 여부별 D7, 구간별 도달률, 신호 인앱 수신 확인·결과 실제 열람을 통해 개선 후보를 검토한다.
- 친구 상태 변경과 결과 열람은 별도 행동 기록을 추가한 시점부터 분석한다. 기존 관계 행·일괄 `seenAt`을 정확한 전환 이력으로 쓰지 않는다.
- 수용 기준: 비교 집단·표본 수·관찰 기간을 함께 표시하고, 상관관계를 인과 효과로 단정하지 않는다.
