# 0010. 관리자 전용 페이지와 독립 마스터 인증

2026-09-20 · 결정됨 · F5-1

## 맥락

사용자 요청에 따라 관리자 페이지를 별도로 구분하고 전용 마스터 계정으로 로그인한다. 일반 회원의 권한을 승격하는 방식 대신 관리자 신원과 세션을 별도 관리한다.

현재 앱은 `app/web`의 Next.js, better-auth, Prisma를 사용한다. 이번 결정은 같은 앱·배포 안에서 화면과 인증을 분리하는 범위다. 별도 도메인이나 관리자 앱 배포는 추가하지 않는다.

## 결정

### 화면과 로그인 동선

```text
일반 서비스: /login       → 일반 User 인증  → 일반 Session → 레이스·친구·마이
관리자:      /admin/login → 마스터 인증     → AdminSession → /admin 대시보드
```

- 관리자 전용 로그인 폼과 레이아웃을 만든다. 일반 로그인·가입 화면에 관리자 진입 메뉴를 넣지 않는다.
- `/admin/login`은 공개 로그인 화면, `/admin` 이하의 대시보드는 마스터 인증이 필요한 화면이다. 로그인 페이지는 `(protected)` 라우트 그룹의 바깥에 둔다.
- 일반 계정으로 로그인해도 관리자 화면은 마스터 로그인을 요구한다. 각 보호 API에서도 독립적으로 검사한다.
- 관리자 상단에는 마스터 표시와 관리자 로그아웃을 둔다. 마스터 로그인이 일반 앱 로그인까지 만들어 주지는 않는다.

### 인증 구조

- 기존 better-auth 인스턴스 `auth`를 유지하고 관리자 전용 `adminAuth`와 전용 클라이언트를 만든다. 인증 라이브러리와 Prisma 클라이언트는 재사용한다.
- 관리자 인스턴스의 API basePath는 `/api/admin/auth`, 쿠키 접두사는 `tth-admin`, 비밀키는 서버 전용 `ADMIN_AUTH_SECRET`으로 분리한다.
- 인증 모델은 `AdminUser`, `AdminSession`, `AdminAccount`, `AdminVerification`으로 각각 매핑한다. better-auth의 원래 필드 계약과 username 플러그인의 필드는 유지한다.
- `AdminUser`는 초기 마스터 한 명의 신원과 비활성화 시각을 저장한다. `AdminAccount`는 자격 증명, `AdminSession`은 관리자 세션, `AdminVerification`은 인증 라이브러리의 검증 모델 계약을 담당한다.
- 일반 `User`에는 관리자 role을 추가하지 않는다. 기존 세션·계정 테이블과 관리자 테이블 사이에 자동 승격·연결·동기화를 만들지 않는다.
- `getAdmin`·`requirePageAdmin`은 관리자 세션과 DB의 `AdminUser.disabledAt`을 검사한다. 일반 `getCurrentUser`와 별도로 둔다.
- 쿠키는 HttpOnly, 운영 HTTPS에서는 Secure, SameSite 속성과 동일 출처 검증을 적용한다. `/admin` 화면과 `/api/admin` 요청 모두에 전송될 수 있도록 Path는 `/`를 사용하되, 이름·서명키·DB 조회 대상을 나눠 인증 경계를 유지한다. 하위 도메인 공유는 켜지 않는다.
- 세션은 로그인부터 최대 8시간 후 만료하고 자동 연장하지 않는다. 관리자 세션의 쿠키 캐시는 비활성화해 세션 폐기·계정 비활성화를 다음 서버 요청에 반영한다.
- 일반·관리자 로그아웃은 각각 자신의 세션·쿠키만 지운다. 관리자용 QueryClient를 따로 두고 관리자 로그아웃 시 진행 중 요청과 해당 캐시만 비운다.

### 마스터 생성과 복구

- 1차 버전은 마스터 1개를 운영한다. 일반 회원가입 경로로 만들 수 없다.
- 서버 전용 초기화 명령이 전용 신원과 자격 증명을 트랜잭션으로 생성한다. 고정된 내부 마스터 ID와 DB 기본키 제약으로 동시 초기화 시 중복 생성을 막는다. 아이디와 비밀번호는 운영자가 별도 입력한다.
- 초기화 명령은 마스터가 이미 존재하면 변경 없이 종료한다. 배포할 때마다 계정을 재생성하거나 비밀번호를 덮어쓰지 않는다.
- 비밀번호는 라이브러리의 검증 형식에 맞는 해시로 저장한다. 초기 비밀번호·인증 비밀키를 소스·브라우저 번들·로그·마이그레이션에 넣지 않는다.
- 비밀번호 교체·복구 명령은 마스터 자격 증명을 교체하고 모든 관리자 세션을 만료시킨다. 마스터 비활성화 절차도 함께 둔다.
- 런타임 인스턴스는 공개 가입을 비활성화한다. 서버 초기화 명령은 공개 sign-up API를 잠깐 열어 사용하는 방식으로 구현하지 않는다.
- 공개 관리자 인증 핸들러는 아이디 로그인·세션 확인·로그아웃에 필요한 경로와 메서드만 허용한다. 계정 생성·계정 연결·삭제·비밀번호 복구 등 다른 라이브러리 엔드포인트가 직접 노출되지 않도록 한다.
- 로그인 시도는 `admin_login_attempt` 테이블의 원자적 카운터로 전체 1분에 10회 제한하고 신뢰 출처를 실제 배포 출처로 제한한다. 단일 마스터 운영을 위한 전체 제한이며, 서버리스 인스턴스 사이에서도 공유한다.

### 사용자 관리·분석과의 관계

- 사용자 목록과 정지·해제·세션 만료의 대상은 일반 `User`다. 관리자 신원은 목록과 조치 대상에 포함되지 않는다.
- 감사 이력은 `actorAdminId`를 `AdminUser`에, `targetUserId`를 일반 `User`에 연결한다. 라이브러리 두 인스턴스의 `userId`가 서로 다른 신원을 뜻한다는 점을 타입과 서비스 경계에서도 구분한다.
- 마스터는 가입자 수·방문 DAU·친구·랭킹·칭호 집계에 포함되지 않는다. 운영자가 테스트용 일반 계정도 사용한다면 해당 일반 계정은 `analyticsExcluded`로 별도 제외할 수 있다.
- 일반 회원의 정지·탈퇴가 관리자 세션을 건드리지 않고, 마스터 복구가 일반 회원 세션을 건드리지 않아야 한다.

## 대안과 선택 이유

| 방식 | 판단 |
| --- | --- |
| 일반 User에 관리자 role 추가 | 전용 마스터 계정과 인증을 분리하려는 요구에 맞지 않음 |
| 독립 better-auth 인스턴스·인증 테이블 | 채택. 기존 라이브러리를 쓰면서 계정·세션을 구분할 수 있음 |
| 환경 변수 비밀번호 직접 비교·자체 세션 구현 | 해시 검증·만료·폐기 로직을 별도로 유지해야 하므로 채택하지 않음 |
| 별도 관리자 앱·도메인 배포 | 더 강한 실행 환경 분리가 필요해지면 검토. 현재 페이지·인증 분리 범위에는 포함하지 않음 |

## 구현 영향과 수용 기준

- 상세 화면·지표는 [관리자 대시보드 초안](../superpowers/specs/2026-09-20-admin-dashboard-design.md)을 유지하고 인증 경계를 이 ADR로 맞춘다.
- 구현 시 `data-model.md`를 먼저 수정하고 Prisma 모델과 `pnpm db:migrate` 마이그레이션을 추가한다. 새 환경 변수·운영 명령은 `.env.example`, `deploy.md`, `tech-stack.md`에 기록한다.
- 일반 세션만 있는 관리자 페이지는 `/admin/login`으로, 관리자 보호 API는 401로 처리한다. 로그인 페이지와 로그인 API에는 관리자 인증을 선행 요구하지 않는다.
- 양쪽 세션의 로그인·로그아웃·만료가 독립적이어야 한다. 같은 아이디 문자열이 양쪽에 있어도 인증 저장소를 혼용하지 않는다.
- 마스터 비활성화·비밀번호 교체 후 기존 세션이 거절되고, 공개 회원가입·초기화·복구·미허용 인증 경로를 차단한다.
- 관리자의 일반 회원 조회는 일반 앱 로그인 상태를 생성하거나 사용자 데이터를 읽음 처리하지 않는다.

## 확인 근거

2026-09-20, 설치된 better-auth 1.7.5 코드와 공식 문서를 확인했다. 아래 설정을 조합해 독립 인스턴스를 구성하는 것은 이 프로젝트의 설계 결정이며, 실제 핸들러와 로컬 DB 통합 테스트로 인증 저장소·쿠키·로그아웃·세션 폐기의 분리를 검증했다.

- [Better Auth 쿠키](https://better-auth.com/docs/concepts/cookies): 쿠키 접두사·속성 설정.

- [Better Auth 옵션](https://better-auth.com/docs/reference/options): basePath·secret·가입 비활성화·세션 만료·자동 갱신 설정.
- 로컬 `app/web/node_modules/better-auth/dist/cookies/index.mjs`, `api/routes/sign-up.mjs`, `api/routes/session.mjs`: 설치 버전의 접두사·가입 차단·세션 갱신 제어 구현 확인.
