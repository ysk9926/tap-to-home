# 0013. 네이티브 복귀 신호와 WebView 단계적 복구

2026-09-22 · 결정됨

## 맥락

웹은 `visibilitychange`와 `online` 이벤트로 복귀를 감지해 활성 데이터를 보정한다. 하지만 iOS·Android가 앱이나 WebView 콘텐츠 프로세스를 중단한 뒤 복원하면 브라우저 이벤트가 전달되지 않거나 Realtime 연결 상태가 이전 값으로 남을 수 있다. Flutter 셸도 페이지 완료만 관찰해 메인 문서가 실패하거나 멈추면 로딩 표시를 끝내거나 재시도할 방법이 없다.

세션 자체의 만료 시간을 늘리는 것으로는 이 문제를 해결할 수 없다. 유효한 세션도 복귀 이벤트가 없으면 데이터를 보정하지 못하고, 만료된 세션도 요청이 시작되지 않으면 로그인 화면으로 이동하지 못한다.

## 결정

- Flutter는 `AppLifecycleListener`로 백그라운드 진입 시각을 기록하고 `resumed`에서 웹에 `tap-to-home:resume` 이벤트를 전달한다.
- 정상 페이지에는 전체 reload 대신 JavaScript 이벤트를 먼저 보낸다. JavaScript 실행이 2초 안에 끝나지 않거나 실패한 경우에만 현재 URL을 reload한다.
- 웹은 네이티브 resume, `visibilitychange`, `online`을 하나의 보정기로 합친다. 네이티브 resume에서는 Realtime 채널을 직렬로 재시작하고 활성 Query를 한 번 다시 읽는다.
- Flutter는 WebView 상태를 `loading`, `ready`, `failed`로 구분한다. 메인 프레임 로드 오류, 5xx 응답, 15초 로드 제한 초과는 `failed`가 되며 사용자가 다시 시도할 수 있다. 콘텐츠 프로세스가 멈춰 복귀 JavaScript가 실패하면 현재 문서를 다시 불러오고, 그 로드도 실패하면 같은 재시도 화면으로 수렴한다. 하위 리소스 오류는 페이지 전체 실패로 취급하지 않는다.
- 동일 출처 쿠키, 캐시, LocalStorage는 복구 과정에서 지우지 않는다. 세션을 불필요하게 제거하거나 사용자를 매번 로그아웃시키지 않는다.
- 웹 API의 401은 Query와 mutation을 구분하지 않고 공통 세션 종료 경로로 전달한다. 네트워크·5xx는 세션 종료가 아니라 제한 시간과 기존 재시도 정책으로 처리한다.
- 새 모바일 빌드는 `https://taptohome.site`를 직접 연다. 기존 설치본을 위해 구 Vercel 주소의 307 이동은 유지한다.

## 결과

- 짧은 앱 전환은 현재 화면과 미전송 상태를 보존하면서 데이터와 Realtime만 복구한다.
- WebView 프로세스가 응답하지 않을 때만 reload하므로 정상 복귀마다 초기 서버 렌더링과 인증 확인을 반복하지 않는다.
- 네트워크가 없거나 서버가 실패해도 무한 스피너 대신 원인을 설명하는 재시도 화면이 남는다.
- 세션 만료는 저장되지 않는 낙관적 탭으로 보이지 않고 즉시 로그인 화면 전환으로 수렴한다.

## 제외

- 세션 유효 기간 연장은 이 결정에 포함하지 않는다.
- 캐시 삭제, 쿠키 삭제, 앱 복귀마다 무조건 reload하는 방식은 사용하지 않는다.
