# Admin Dashboard Implementation Plan

> Execute with implementation agents for independent file groups and direct integration checks. The user explicitly prohibits code-review agents; all review is performed by the primary agent. No review agents may be spawned.

**Goal:** Ship the approved administrator workspace with independent master login, user operations, and measured product analytics.

**Architecture:** Existing Next.js deployment; independent better-auth models, sessions and cookie namespace for `/admin/login`. Prisma services supply protected JSON APIs. Chart.js React components render aggregate data, and domain events plus daily activity enable prospective retention analysis.

**Spec:** [Dashboard](../specs/2026-09-20-admin-dashboard-design.md), [master authentication](../../decisions/0010-separate-admin-master-auth.md).

## Constraints

- Korean UI, English identifiers. Keep the existing paper/pencil theme.
- Prisma only for DB access; migrations generated by `pnpm db:migrate` after documenting models.
- Preserve the user's unrelated edits, including `race-scene.tsx`.
- Work on `feat/admin-dashboard`; no deployment or production master provisioning.
- No code-review agents. Independent implementation agents may implement designated files and tests.
- Master sessions never authorize ordinary user APIs and vice versa. No public master signup.
- KST dates, mature observation windows, no fabricated metrics before collection.

## Interfaces and test cases

- `getAdmin(headers): Promise<AdminIdentity | null>` and `requirePageAdmin()` use admin auth only; 401 for ordinary cookies. Test by creating both account types, signing in through real handlers, swapping cookies, signing out one session and verifying the other.
- `adminApi(request, action, mutation?)` checks master identity and same-origin writes, returns private no-store JSON and safe errors. Route allowlist exposes username sign-in, get-session and sign-out only.
- `getDashboard(params, now?): Promise<DashboardData>` uses validated inclusive KST from/to dates. Tests: distinct rolling users, incomplete window=null, exact D7, preserved soft-deleted historical activity, 10,000-tap user-days, batch sums.
- `recordActivity(userId, now?, db?)` ensures one `(userId, activityDate)` row and throttles lastSeen updates. Tests: repeated and concurrent visits, KST midnight, suspended users rejected.
- `moderateUser(adminId, userId, action, reason)` locks the actor and target, atomically updates status/sessions/tokens/audit. Tests: suspend, unsuspend, revoke, excluded population, missing/deleted targets, disabled master, rollback.
- UI queries `/api/admin/{overview,analytics,engagement,users,audit}` and `/api/admin/users/[userId]`; mutations POST to `/suspend`, `/unsuspend`, `/revoke-sessions`, `/analytics-exclusion` with reason. Dates and filters persist in URL.
