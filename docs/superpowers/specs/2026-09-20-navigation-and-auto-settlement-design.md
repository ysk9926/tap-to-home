# 하단 탭 개편과 자동 정산 설계

2026-09-20

## 왜

하단 탭이 5개(레이스·랭킹·친구·오늘·도감)로 꽉 찼는데, 그 중 둘이 자리값을 못 한다.

- **"오늘"** 은 이름이 무엇을 하는 화면인지 말하지 않고, 본체가 "오늘 정산" 버튼이다. 사용자가 하루의 끝을 직접 선언해야 정산이 되는데, 이 앱의 하루는 자정에 끝난다. 정산을 누르지 않고 잠들면 칭호가 영영 없다.
- **"도감"** 은 매일 볼 화면이 아니다. 하루에 한 번 늘어나는 수집함이 상시 탭을 차지하고, 로그아웃 버튼이 갈 곳이 없어 도감 바닥에 붙어 있다(F0-5 가 그 사정을 그대로 적고 있다).

동시에 계정 관련 기능(내 정보 변경, 이용약관, 계정 탈퇴)이 들어갈 자리가 아예 없다.

그래서 탭을 **레이스·랭킹·친구·마이페이지** 4개로 재편하고, 정산을 자정 배치로 옮긴다.

## 무엇을

### 1. 내비게이션

```
레이스 /            내 진행 + [기록보기] 버튼
랭킹   /ranking     (변경 없음)
친구   /friends     (변경 없음)
마이   /my          신설
```

| 기존 경로 | 이후 |
| --- | --- |
| `/today` | 삭제. `/records` 로 리다이렉트 |
| `/collection` | `/my/collection` 로 이동. 기존 경로는 리다이렉트 |
| `/privacy` | 그대로 유지. `/my/privacy` 를 따로 두고 본문 컴포넌트를 공유한다 |

`/privacy` 를 리다이렉트로 바꾸지 않는 이유: `/my/*` 는 인증 레이아웃 아래라 로그인하지 않은 사람이 열면 `/login` 으로 튕긴다. 앱스토어 심사자는 로그인 없이 이 URL 을 연다.

`/my` 하위:

```
/my                  허브 — 닉네임·@아이디 + 메뉴 5줄 + 로그아웃 + 계정 탈퇴
/my/profile          내 정보 (닉네임 · 비밀번호 · 알림 설정)
/my/collection       퇴근 도감
/my/terms            이용약관
/my/privacy          개인정보처리방침
/my/delete           계정 탈퇴
```

`/records` 는 탭이 아니다. 레이스 화면의 "기록보기" 버튼으로만 들어가고 뒤로 가기로 `/` 에 돌아온다.

허브의 도감 줄만 우측에 획득 수(`14/50`)를 표시한다. 메뉴가 전부 같은 모양의 줄이면 죽은 목록처럼 보인다.

계정 탈퇴는 로그아웃보다 아래, 연한 글씨로 한 단 낮춘다.

### 2. 자동 정산 배치

**트리거.** `vercel.json` 의 cron 이 매일 KST 00:05(UTC 15:05)에 `GET /api/cron/settle` 을 호출한다. 자정 정각이 아닌 이유: 23:59:5x 의 탭이 커밋될 여유를 두고, 스케줄러가 분 단위로 밀려도 날짜 경계를 넘지 않게 한다.

**인증.** `Authorization: Bearer ${CRON_SECRET}` 을 확인하고 불일치·부재면 401. 공개 URL 이라 누구나 정산을 돌릴 수 있으면 안 된다.

**대상.** 어제(KST) `runDate` 의 `daily_run` 중 `tapCount > 0` 이고 `daily_result` 가 없는 행. 탭 0회 유저는 정산도 알림도 없다.

**실행.** 기존 `settleToday(user, now)` 를 `settleRun(user, runDate)` 로 바꿔 날짜를 인자로 받는다. 배치는 대상 id 목록을 먼저 뽑고 **한 번에 5건씩 순차 처리**한다 — Supabase 커넥션 풀이 5개뿐이라 전체를 `Promise.all` 로 던지면 정산 하나가 트랜잭션과 랭킹 조회로 커넥션을 잡는 동안 풀이 마른다. 한 건이 실패해도 배치는 계속 돌고 실패한 `dailyRunId` 목록만 응답에 남긴다.

**멱등성.** 크론이 두 번 발화하거나 재시도돼도 안전하다. `settleRun` 은 `daily_run` 행을 `SELECT ... FOR UPDATE` 로 잠근 뒤 `result` 가 있으면 저장된 결과를 그대로 돌려준다. 기존 코드가 이미 이 성질을 갖고 있어 새로 만들 것이 없다.

**수동 정산 제거.** `settleTodayAction` 과 "오늘 정산" 버튼을 삭제한다. 사용자가 하루를 스스로 끝낼 방법이 사라지므로 `/records` 의 오늘 카드가 "자정에 자동으로 정산돼요" 를 명시한다.

**알림.** 정산에 성공한 유저마다 FCM 푸시 1건. 문구는 대표 칭호 기준 — 칭호가 있으면 `오늘 당신은 '마음만 이미 집에 있음'`, 없으면 `어제 1,204번 퇴근하고 싶었어요`. payload 에 날짜를 실어 탭하면 `/records/2026-09-19` 를 연다. 토큰이 없거나 `notifySettlement = false` 인 유저는 건너뛴다 — 진입 다이얼로그(아래 4)가 받아준다.

### 3. 기록 보기

**`/records`** — 맨 위에 **오늘 카드**(진행 중, 회색톤: 횟수·첫 탭 시각·현재 순위 + "자정에 자동 정산돼요"), 그 아래 정산 완료된 날들이 최신순. 각 줄은 `9월 19일 · 마음만 이미 집에 있음 · 1,204회 · 2위` 한 줄 요약과 대표 칭호 포즈 썸네일. 그날 새로 얻은 칭호가 있으면 NEW 배지.

**`/records/[date]`** — `2026-09-19` 형식. 그날의 총 횟수·첫 탭 시각·랭킹·획득 칭호 전체 그리드. 기존 `/today` 의 정산 완료 화면을 옮기며 `TodayResultCard` 를 재사용한다. 하단에 "도감 전체 보기" → `/my/collection`.

**데이터.** `daily_run` + `daily_result` 조인 쿼리 하나(`features/titles/server/record-list.ts`). **최근 30일 고정**, 페이지네이션 없음 — 앱이 막 시작한 상태라 아직 실체 없는 문제다.

### 4. 정산 결과 전달

푸시는 Flutter 웹뷰 셸에서만 동작한다. 브라우저 접속자와 푸시 미허용자에게도 결과가 닿아야 한다.

`daily_result.seenAt` 을 추가하고, 앱 레이아웃이 세션 확인 직후 **아직 안 본 정산 결과 중 가장 최근 1건**을 읽어 진입 다이얼로그로 띄운다. 대표 칭호와 순위를 보여주고 "기록 보기" / "닫기" — 어느 쪽이든 `seenAt` 을 채워 다시 뜨지 않게 한다.

친구 요청 다이얼로그(F0-3)와 자리가 겹치므로 **정산 결과가 먼저, 닫은 뒤 친구 요청** 순서를 고정한다.

푸시를 탭해 `/records/[date]` 로 바로 들어온 경우 그 화면이 `seenAt` 을 채운다. 이미 본 결과가 배너로 또 뜨면 안 된다.

며칠 자리를 비워 안 본 결과가 여러 건 쌓였다면 **가장 최근 1건만 띄우고 나머지는 같이 `seenAt` 을 채운다**. 다이얼로그를 세 번 닫게 하는 것보다, 어제 결과를 보여주고 "지난 기록 보기" 로 `/records` 를 가리키는 편이 낫다.

레이아웃은 이미 `getFriendsState` 를 한 번 읽는다. 여기에 인덱스가 받쳐주는 `findFirst` 하나가 더해진다.

### 5. 마이페이지

**`/my/profile`** — 세 블록이 한 화면에.

- *닉네임* — 인풋 + 저장. 1~12자, 서버 액션에서 재검증.
- *비밀번호 변경* — 현재 비번 + 새 비번 + 확인. better-auth `changePassword` 가 현재 비번을 요구한다. 성공해도 다른 기기 세션은 유지한다(혼자 쓰는 앱이라 강제 로그아웃은 과하다).
- *알림* — 스위치 2개: `퇴근 신호 알림`(`notifySignal`), `정산 결과 알림`(`notifySettlement`). 끄면 서버가 푸시 발송 전에 거른다. **인앱 토스트와 진입 다이얼로그는 설정과 무관하게 뜬다** — 앱을 직접 열었을 때 보는 화면이지 알림이 아니다.

아이디는 읽기 전용이다. 친구 검색 키라 바뀌면 상대의 "보낸 요청" 이 끊긴다.

**`/my/collection`** — 기존 `/collection` 을 그대로 옮기고, 바닥의 로그아웃 버튼을 제거한다(허브로 갔다). F0-5 문서도 함께 고친다.

**`/my/terms`, `/my/privacy`** — 정적 본문. 개인정보 처리방침 본문은 컴포넌트로 빼서 `/privacy` 와 `/my/privacy` 가 함께 쓴다. `/terms` 초안은 서비스 성격(친구 간 레이스)·계정·금지행위·면책·문의처의 최소 구성으로 새로 쓴다.

**`/my/delete`** — 무엇이 사라지는지 먼저 알리고(친구 관계·레이스 기록·도감), **자기 아이디를 직접 입력**해야 버튼이 활성화된다. 실행하면 소프트 삭제 후 세션을 파기하고 `/login` 으로 보낸다.

### 6. 소프트 삭제

소프트 삭제의 유일한 실패 모드는 **필터를 한 군데 빠뜨려 탈퇴 유저가 랭킹·검색에 유령으로 남는 것**이다. "모든 쿼리에서 조심하기" 로 막지 않고 구조로 막는다.

**활성 유저 조회를 한 곳으로.** `src/lib/db/active-user.ts` 에 `ACTIVE_USER = { deletedAt: null }` 하나를 두고, 유저를 대상으로 하는 모든 `where` 가 이 상수를 펼쳐 쓴다. 대상은 네 곳이다:

1. 친구 검색 (`features/friends/server` 의 아이디 조회)
2. 친구 목록 조회 (`getFriendsState`)
3. 레이스·랭킹 조회 (`getRaceToday`)
4. 세션 검증 (`getCurrentUser`)

네 곳 각각에 "탈퇴한 유저는 보이지 않는다" 테스트를 붙인다. 필터를 빠뜨리면 사람이 눈치채는 게 아니라 테스트가 빨간불이 된다.

**친구 관계는 그대로 둔다.** 탈퇴자의 `friendship` row 를 지우지 않고 조회 시 필터로 거른다. 복구하면 관계가 돌아오는 것이 소프트 삭제의 취지고, row 를 지우면 그 취지가 반만 남는다.

**로그인 차단.** `getCurrentUser` 가 `deletedAt` 이 있는 유저를 세션 없음으로 취급한다. 살아있던 세션도 다음 요청에 끊긴다.

**아이디 재사용 금지.** 가입 시 중복 검사는 탈퇴자를 포함한 전체를 본다(better-auth 의 unique 제약이 그대로 작동). 탈퇴한 아이디로는 재가입할 수 없다.

## 스키마 변경

`docs/data-model.md` 를 먼저 고치고 `schema.prisma` 에 반영한 뒤 `pnpm db:migrate` 로 마이그레이션 1개를 만든다.

| 테이블 | 컬럼 | 용도 |
| --- | --- | --- |
| `user` | `deletedAt DateTime?` | 소프트 삭제 |
| `user` | `notifySignal Boolean @default(true)` | 퇴근 신호 알림 on/off |
| `user` | `notifySettlement Boolean @default(true)` | 정산 결과 알림 on/off |
| `daily_result` | `seenAt DateTime?` | 진입 다이얼로그 1회 표시 |

## 문서

- `docs/features.md` — F0-5(로그아웃 위치), F3(정산 시점), 새 F4(마이페이지) 를 반영한다.
- `docs/decisions/0008-nightly-settlement-cron.md` — 수동 정산에서 크론 배치로 옮긴 결정과, lazy 정산(접속 시 전날 정산)을 택하지 않은 이유(자정 알림이 불가능)를 남긴다.
- 소프트 삭제는 ADR 을 쓰지 않는다. 기술 선택의 변경이 아니라 이 기능의 구현 세부이고, 근거는 위 6절이 담는다. `data-model.md` 에 주석으로 남긴다.

## 하지 않는 것

- 기록 목록의 페이지네이션·무한 스크롤 (30일 고정)
- 탈퇴 유예 기간과 복구 UI (`deletedAt` 은 있지만 되돌리는 화면은 없다. 필요하면 DB 에서 푼다)
- 알림 시각 설정, 방해 금지 시간대
- 프로필 이미지
- 아이디 변경

## 완료 기준

- `pnpm typecheck`, `pnpm lint`, `pnpm test` 통과
- `prisma/migrations/*` 가 커밋에 포함
- 탭이 4개이고 `/today`·`/collection`·`/privacy` 접속이 새 경로로 리다이렉트된다
- 탭 1회 이상인 유저만 정산되고, 정산된 유저에게 알림이 발송된다
- 탈퇴한 유저가 친구 검색·친구 목록·랭킹에 나타나지 않고 로그인할 수 없다 (각각 테스트)
