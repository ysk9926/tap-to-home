# 관리자 페이지·운영 대시보드 구성 초안

2026-09-20 · 승인된 설계 · F5 · 구현 기준과 초기 와이어프레임

## 1. 목적과 범위

**누가 가입하고, 얼마나 다시 찾아오며, 어느 경험에서 멈추는지 확인하고 사용자를 관리하는 운영 공간**을 `/admin`에 둔다. 숫자를 나열하는 데서 끝내지 않고, 가입 과정·레이스 난이도·친구 연결·칭호 보상 중 무엇을 먼저 개선할지 판단하게 한다.

2026-09-20 사용자 방향 반영: **관리자는 별도 페이지와 `/admin/login` 전용 로그인, 일반 회원과 분리된 마스터 계정으로 접근한다.** 화면·계정·세션을 분리하고, 현재 Next.js 앱과 배포 안에서 운영한다. 별도 도메인·별도 앱 배포는 이번 초안에 포함하지 않는다. 인증 설계는 [ADR 0010](../../decisions/0010-separate-admin-master-auth.md)을 따른다.

초안 검토 후 사용자 승인을 받아 아래 경로·API·모델·차트를 구현했다. 마이그레이션은 로컬 개발 DB에 적용했으며, 운영 DB 반영과 운영 마스터 계정 생성은 배포 시 수행한다. 설정·계정 관리 절차는 [배포 문서](../../deploy.md), 구현·검증 기록은 [구현 계획](../plans/2026-09-20-admin-dashboard.md)을 따른다. 아래 와이어프레임과 단계 구분은 최초 설계 기록이다.

차트 라이브러리는 **`react-chartjs-2` + Chart.js 4**를 사용한다. 요청의 “react-chart”를 React 차트 라이브러리 사용으로 해석한 선택이며, 별도 패키지인 TanStack `react-charts`와는 다르다. 선택 근거와 대안은 [ADR 0009](../../decisions/0009-admin-dashboard-and-charts.md)에 정리한다.

### 구성 방식 비교

| 방식 | 장점 | 비용·한계 |
| --- | --- | --- |
| **기존 Next.js에 관리자 전용 페이지·마스터 로그인 구성 — 채택 방향** | Prisma·디자인 토큰과 인증 라이브러리 재사용, 마스터 계정·세션은 독립 | 별도 인증 인스턴스·테이블과 분석 수집 필요 |
| 별도 관리자 앱 | 배포와 UI를 독립적으로 운영 | 인증·API·배포 경계가 늘어 현재 규모에 부담 |
| 외부 분석 도구 + 별도 사용자 관리 | 탐색 분석을 빠르게 시작할 수 있음 | 계정 관리 화면은 여전히 필요하고 데이터가 분산됨 |

## 2. 관리자가 답을 얻어야 하는 질문

| 질문 | 볼 지표 | 다음 개발 후보 |
| --- | --- | --- |
| 가입했는데 바로 시작하지 못하나? | 가입 후 30초 내 첫 탭, 24시간 내 첫 탭 | 가입 완료 화면·첫 탭 안내 |
| 사람들이 며칠 뒤에도 돌아오나? | 방문 DAU/WAU/MAU, D1·D7 재방문 | 다음 날 진입 동기·칭호 보상 |
| 만 번을 누르는 레이스가 적절한가? | 완주율, 구간별 도달률, 플레이일별 탭 중앙값 | 구간 간격·하루 목표·중간 보상 |
| 친구를 연결하면 더 자주 돌아오나? | 가입 24시간 내 친구 연결 여부별 D7 | 친구 초대·요청 수락 안내 |
| 신호와 칭호가 실제로 소비되나? | 신호 인앱 수신 확인율, 결과 실제 열람률 | 신호 표현·결과 화면 진입 |
| 운영상 문제가 있는 계정이 있나? | 계정 상태·최근 방문·제재 이력 | 사용자 지원·이용 제한 |

차트 옆에는 `관찰 → 확인할 가설 → 개발 후보`를 적는다. 친구가 있는 사용자의 재방문이 높아도 친구 기능의 인과 효과라고 단정하지 않는다. 초기에는 표본 수를 함께 보고, 자동 추천 점수나 근거 없는 업계 목표치는 넣지 않는다.

## 3. 메뉴와 화면

| 메뉴 | 제안 경로 | 핵심 내용 |
| --- | --- | --- |
| 관리자 로그인 | `/admin/login` | 마스터 아이디·비밀번호, 관리자 전용 로그인 |
| 전체 현황 | `/admin` | 핵심 지표, 일별 추이, 레이스 구간 도달률, 운영 확인 항목 |
| 접속·재방문 | `/admin/analytics` | 방문 추이, 접속률, 가입 활성화, 가입 코호트별 재방문 |
| 레이스·소셜 | `/admin/engagement` | 완주, 탭 시간대, 친구 연결, 신호·칭호 이용 |
| 사용자 관리 | `/admin/users` | 전체 계정 검색·필터·정렬, 사용자 상세 |
| 사용자 상세 | `/admin/users/[userId]` | 계정·플레이·친구·칭호 요약, 정지·해제·세션 만료 |
| 관리 이력 | `/admin/audit` | 관리자 조치자·대상·사유·변경 시각 |

로그인 후 첫 화면은 네 개의 주 메뉴를 쓴다. 관리 이력은 사용자 관리 하위에 둔다. 관리자 진입 URL은 `/admin/login`이며, 일반 사용자의 로그인·가입·하단 탭과 연결하지 않는다.

### 관리자 로그인 와이어프레임

```text
                  Tap to Home · 관리자
                  운영자 전용 로그인

                  마스터 아이디
                  [                     ]
                  비밀번호
                  [                     ]
                  [  관리자 로그인      ]
```

- 회원가입·일반 로그인·소셜 로그인 메뉴 없이 마스터 로그인 폼만 둔다.
- 성공하면 `/admin`, 실패하면 `아이디 또는 비밀번호를 확인해 주세요`를 표시한다. 마스터 계정의 존재 여부를 구분해서 알리지 않는다.
- 관리자 세션이 없거나 만료되면 `/admin/login`으로 이동한다. 일반 회원으로 이미 로그인했어도 마스터 로그인이 필요하다.
- 로그인 페이지는 관리자 보호 레이아웃 밖에 둬 반복 리다이렉트를 막는다. 인증된 마스터가 로그인 페이지를 열면 `/admin`으로 보낸다.

### 전체 현황 와이어프레임

아래는 배치 예시다. `—`는 실데이터를 조회하지 않았다는 뜻이며 0명이 아니다.

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Tap to Home · 운영 노트                           마스터  [로그아웃]      │
├───────────────┬──────────────────────────────────────────────────────────┤
│ ● 전체 현황   │ 전체 현황                                                │
│ 접속·재방문   │ [최근 7일 ▾] [이전 기간 비교]   KST · 마지막 집계 —        │
│ 레이스·소셜   │                                                          │
│ 사용자 관리   │ 현재 정상 회원 —명      기간 신규 가입 —명                │
│   관리 이력   │ 일평균 방문 —명         접속률 DAU/MAU —%                 │
│               │ D7 재방문 —%            플레이일 완주율 —%                │
│               │                                                          │
│               │ ┌ 일별 방문·플레이 추이 ─────────┬ 레이스 구간 도달률 ─┐ │
│               │ │ 실선: 방문 / 점선: 플레이       │ 첫 탭       ━━━━━━ │ │
│               │ │                                 │ 엘리베이터  ━━━━━  │ │
│               │ │ Line · 같은 단위(명)            │ 로비        ━━━━   │ │
│               │ │                         [표 보기]│ … / 집      ━━     │ │
│               │ └─────────────────────────────────┴────────────────────┘ │
│               │ ┌ 가입 코호트별 재방문 ───────────┬ 운영 확인 ─────────┐ │
│               │ │ 가입일 / 대상 수 / D1 / D7      │ 정산 누락 —건      │ │
│               │ │ 표 + 셀 명도                    │ 계측 수집 상태     │ │
│               │ │ 관찰 중인 날짜는 ‘관찰 중’      │ [관련 사용자 보기] │ │
│               │ └─────────────────────────────────┴────────────────────┘ │
└───────────────┴──────────────────────────────────────────────────────────┘
```

화면 상단에 수치 카드 여섯 개, 가운데에 넓은 추이 차트와 좁은 구간 차트, 아래에 재방문 표와 운영 항목을 둔다. 카드에는 기준일·단위·비교 기간을 적고, 비율 툴팁에는 분자와 분모도 보여준다.

- 기본 기간: 어제까지 완료된 최근 7일. 최근 30일·90일·직접 선택을 제공하고 최대 90일로 제한한다.
- 오늘은 별도 선택이며 `집계 중`을 표시한다. 완료된 어제와 오늘의 부분 수치를 그대로 증감 비교하지 않는다.
- 기간 합계·평균은 바로 앞의 같은 길이 기간과 비교한다. 비율의 차이는 `%p`, 인원 증감은 `%`와 명수를 쓴다. 이전 값이 0이면 증감률은 `비교 불가`다.
- 현재 정상 회원은 기간과 무관한 현재 스냅샷이다. 기간 필터가 적용되는 신규 가입·일평균 방문과 라벨을 구분한다.
- DAU/MAU 카드는 선택 기간 마지막 완료일 기준이다. D7 카드는 선택 기간에 가입했고 D7 관찰일이 끝난 사람만 합쳐 계산한다.
- 카드나 구간을 누르면 해당 날짜·조건을 유지한 상세 분석 또는 사용자 목록으로 이동한다.
- 수집 시작 전은 `수집 전`, 분모 0은 `대상 없음`, 관찰 기간 미완료는 `관찰 중`, 서버 실패는 `불러오지 못했어요`로 구분한다.

### 사용자 관리 와이어프레임

```text
사용자 관리                                전체 — / 정상 — / 정지 — / 탈퇴 —
[아이디·닉네임·사용자 ID 검색            ] [계정 상태 ▾] [활동 상태 ▾]
[가입일 범위] [친구 유무 ▾] [최근 가입순 ▾]                  [필터 초기화]

닉네임 / 아이디     계정 상태    가입일     최근 방문     최근 탭     친구
────────────────────────────────────────────────────────────────────────
사용자 행          정상         날짜       시각          시각        수
사용자 행          이용 정지    날짜       시각          시각        수
                                                     [이전] 1 [다음]

행 선택 → 사용자 상세
계정 정보 | 최근 30일 플레이 | 친구·칭호 요약 | 관리 이력
[이용 정지] [정지 해제] [모든 기기 로그아웃]
```

- 계정 상태와 활동 상태를 분리한다. 7일간 방문하지 않았다고 계정을 정지·휴면 처리하지 않는다.
- 활동 필터: `최근 7일 방문`, `최근 7일 방문 없음`, `가입 후 탭 없음`. 계측 이전 방문은 `미수집`으로 표시하고 미방문으로 단정하지 않는다.
- 기본 페이지 크기는 25명, 최대 100명. 검색·정렬·페이지 처리는 서버에서 한다. 정렬은 가입일·최근 방문·기간 탭 수를 허용하고 동률은 사용자 ID로 정한다.
- 상세의 친구 수는 현재 수락 상태이며 탈퇴·정지 상대를 제외한다. 한 사람의 현재 관계 요약을 과거 친구 수로 해석하지 않는다.
- 로그인용 가상 이메일, 비밀번호 해시, 세션 토큰, FCM 토큰, IP·User-Agent 원문은 화면이나 관리자 API 응답에 넣지 않는다.
- 1차 조치는 이용 정지·해제와 모든 세션 만료다. 계정 영구 삭제·탈퇴 복구·대량 제재·CSV 개인정보 내보내기는 후속 범위로 둔다. 마스터 계정 생성·편집은 사용자 관리 화면에 넣지 않는다.
- 이용 정지에는 사유 입력과 대상 확인을 둔다. 요청 중 중복 클릭을 막고, 실패하면 상태를 원래대로 유지한다. 조치 대상은 일반 `User`만이며 마스터 계정은 목록과 제재 대상에 포함되지 않는다.

## 4. 지표 정의

### 공통 기준

모든 날짜는 KST의 `[00:00, 다음 날 00:00)`다. 저장 시각은 UTC를 쓰고 기간 경계 변환은 서버에서 한다. 기존 `runDate`는 KST 날짜이므로 시각처럼 다시 9시간 이동하지 않는다.

제품 분석은 지정된 운영·테스트용 일반 회원 계정을 제외한다. 현재의 `analyticsExcluded` 계정 목록을 가입·방문·탭·코호트의 분자와 분모에 동일하게 적용한다. 제외 대상을 바꾸면 과거 분석도 다시 계산되므로 필터 변경 사실을 표시한다. 전체 계정 관리 화면은 테스트·정지·탈퇴 계정도 조회할 수 있다. 마스터 계정은 별도 인증 테이블에 있으며 전체 회원 수·친구·랭킹·접속 통계에 들어가지 않는다.

탈퇴·정지가 발생해도 이전에 실제로 일어난 방문·탭을 과거 분석에서 지우지 않는다. 계정 상태 카드와 과거 행동 지표의 모집단은 다르다. 원본 삭제가 필요해지는 경우에는 비식별 집계 보존과 과거 통계의 재계산 정책을 별도로 정한다.

### 우선 표시할 지표

| 지표 | 정확한 정의 | 현재 데이터로 가능? |
| --- | --- | --- |
| 현재 정상 회원 | 조회 시점 `deletedAt = null`, 정지 아님인 계정 수. 운영·테스트 제외 | 회원 수는 가능. 정지·제외 필드는 추가 필요 |
| 기간 신규 가입 | `User.createdAt`이 선택 기간에 속한 계정 수 | 가능 |
| 플레이 DAU | 해당 `runDate`에 `tapCount > 0`인 고유 사용자 수 | 가능. 방문 DAU와 다른 지표 |
| 방문 DAU | 해당 KST 날짜에 인증된 앱 화면을 전경에서 연 고유 사용자 수 | 방문 계측 추가 필요 |
| 방문 WAU / MAU | 기준일 포함 직전 7일 / 30일에 방문한 고유 사용자 수 | 방문 계측 추가 필요. 일별 DAU 합계가 아님 |
| 접속률(DAU/MAU) | 기준일 방문 DAU ÷ 같은 기준일 방문 MAU × 100 | 30일 수집 완료 후 표시. 전체 가입자 대비 비율과 구별 |
| 방문자의 플레이 참여율 | 그날 방문자 중 1회 이상 탭한 사람 ÷ 그날 방문자 × 100 | 방문 계측 추가 필요 |
| 가입 후 30초 내 첫 탭 | 가입 후 30초 이내 첫 저장 탭이 있는 가입자 ÷ 관찰 30초가 지난 가입자 × 100 | 가능. 300ms 배치·네트워크 지연이 포함된 서버 관측치 |
| 가입 후 24시간 내 첫 탭 | 가입 후 24시간 이내 첫 탭이 있는 가입자 ÷ 관찰 24시간이 지난 가입자 × 100 | 가능 |
| 가입 코호트 D1 / D7 | 가입일 D의 가입자 중 D+1 / D+7 KST 날짜에 방문한 사람 ÷ 그 관찰일이 완료된 가입자 × 100 | 방문 계측 추가 필요 |
| 플레이일 완주율 | `tapCount >= 10000`인 사용자·날짜 쌍 ÷ `tapCount > 0`인 사용자·날짜 쌍 × 100 | 가능. 여러 날을 선택해도 고유 사용자 비율로 섞지 않음 |
| 구간 도달률 | 각 임계값 이상 탭한 사용자·날짜 쌍 ÷ 1회 이상 탭한 사용자·날짜 쌍 × 100 | 가능. 누적 도달률이며 합계가 100%일 필요 없음 |
| 플레이일 탭 중앙값 | 1회 이상 탭한 `DailyRun.tapCount`의 중앙값 | 가능. 헤비 유저에 치우친 평균을 보완 |
| 신호 24시간 내 인앱 수신 확인율 | 발송 후 24시간 내 `readAt`이 기록된 신호 행 ÷ 발송 후 24시간 관찰이 끝난 신호 행 × 100 | 가능. 발신·수신자가 분석 대상인 행, 수신자별 전달 건수 기준 |
| 결과 24시간 내 상세 열람률 | 정산 후 24시간 내 실제 상세 열람이 있는 결과 ÷ 정산 후 24시간 관찰이 끝난 결과 × 100 | 실제 열람 이벤트 추가 필요 |
| 정산 누락 | 완료된 날의 `tapCount > 0`인 run 중 결과가 없는 수 | 가능. 당일은 제외, 어제 건은 00:30 이후 확인 대상으로 표시 |

`DAU/MAU`는 해당 월에 방문한 사람 중 오늘도 온 비중을 보는 사용 빈도 지표다. 월간 가입자 중 방문한 비율이나 로그인 성공률과 혼용하지 않는다. 7일·30일 창 전체가 수집되지 않았다면 각각 `수집 중`으로 표시한다.

D7은 가입 다음 날부터 7일 안에 한 번이라도 온 비율이 아니라, **정확히 가입일+7일에 방문했는지**다. 가입자에는 첫 탭이 없는 사람도 포함한다. 날짜별 비율의 단순 평균 대신 분자·분모를 합쳐 계산하며, 표본이 30명 미만이면 `표본 적음`을 병기한다. 이는 통계적 유의성 기준이 아닌 표시 규칙이다.

방문 코호트는 가입일 시작부터 관찰일 종료까지 계측이 운영된 가입일만 대상으로 삼는다. 수집을 시작한 첫날이 불완전하면 다음 KST 날짜부터 코호트를 만든다. 신호와 결과의 24시간 비율은 각각 선택 기간에 발송·정산된 건을 묶고, 현재까지 관찰 시간이 채워진 건만 분모에 넣는다.

### 현재 데이터 해석에서 피해야 할 오류

- `Session.updatedAt`·미만료 세션 수는 최근 방문·동시 접속자를 뜻하지 않는다. `PushToken.updatedAt`도 접속 기록이 아니다.
- `DailyRun`은 정산 경로에서도 만들어질 수 있다. row가 있다는 이유로 방문·플레이를 집계하지 않는다.
- `TapEvent` 한 행은 탭 하나가 아니라 배치다. 횟수는 `sum(batchSize)`이며, 시간대는 실제 손가락 탭 시각이 아닌 서버 수신 시각이다.
- `Friendship`은 거절·취소·삭제 시 행이 사라지고 상태가 바뀐다. 현재 `accepted / 전체 row`는 과거 친구 요청 수락률이 아니다.
- `DailyResult.seenAt`은 최신 결과 다이얼로그를 닫을 때 다른 미확인 결과까지 채워진다. 개별 결과의 실제 열람률로 쓸 수 없다.
- `Signal.readAt`은 인앱 수신 확인이다. 푸시 전달 성공·푸시 클릭·사용자의 실제 인지율로 표현하지 않는다.
- 푸시 토큰 보유 기기 비율은 웹/iOS/Android의 방문 비율이 아니다. 플랫폼별 접속 지표와 실시간 온라인 수는 1차 범위에서 제외한다.

가입 활성화 막대는 24시간 관찰이 끝난 가입 코호트만 비교한다. 친구 연결별 D7은 연결 이벤트 수집이 시작된 뒤의 가입자만 대상으로 삼고, 가입 후 24시간까지 연결된 수락 관계가 한 번이라도 있었는지로 집단을 고정한다. 현재 친구 수로 과거 그룹을 나누지 않는다.

레이스 구간 차트는 이탈 확정률이 아니다. 여러 날의 일일 도달 기록이며, 오늘 포함 시에는 아직 플레이 중인 사람도 있다. 차트 제목은 `구간별 도달률`로 유지한다. 시간대 탭 수와 인원은 단위가 다르므로 이중 Y축으로 겹치지 않는다.

### 화면 스타일과 접근성

- 기존 줄노트·연필 테마를 운영용 노트처럼 확장한다. `paper`, `paper-2`, `pencil`, `marker`, `line` 토큰을 재사용한다.
- 제목에는 기존 손글씨 서체를 쓰고, 촘촘한 표·축 눈금에는 읽기 쉬운 한국어 시스템 서체와 고정폭 숫자를 쓴다. 구현 전에 이 구분을 `design.md`에 추가한다.
- 형광펜 노랑은 현재 메뉴 한 곳에 사용한다. 차트는 연필색의 실선·점선·마커 모양으로 구별하고, 다색 도넛이나 3D 효과를 넣지 않는다.
- 데스크톱: 216px 사이드바, 본문 최대 1,280px, 차트 2열. 1,024px 미만: 접는 메뉴와 1열 차트. 640px 미만: 지표 카드 2열, 사용자 행은 핵심 필드 카드로 전환한다.
- 차트에 제목·텍스트 요약·동일 데이터 표를 제공한다. Canvas 그림이나 hover 툴팁만으로 정보를 전달하지 않는다. [Chart.js 접근성 문서](https://www.chartjs.org/docs/latest/general/accessibility.html)
- 각 Canvas는 높이가 정해진 전용 컨테이너를 쓰고, 폭 변경에 맞춰 크기를 조절한다. [Chart.js 반응형 문서](https://www.chartjs.org/docs/latest/configuration/responsive.html)
- 로딩은 영역별 골격, 빈 결과는 설명과 필터 초기화, 오류는 재시도 버튼을 둔다. `prefers-reduced-motion`에서는 차트 애니메이션도 끈다.

## 6. 마스터 전용 인증과 사용자 조치

### 계정·로그인·세션 분리

| 구분 | 일반 서비스 | 관리자 |
| --- | --- | --- |
| 로그인 화면 | `/login` | `/admin/login` |
| 로그인 API | `/api/auth/*` | `/api/admin/auth/*` |
| 인증 인스턴스 | 기존 `auth` | 별도 `adminAuth` |
| 인증 테이블 | `User`, `Session`, `Account`, `Verification` | `AdminUser`, `AdminSession`, `AdminAccount`, `AdminVerification` |
| 계정 생성 | 일반 회원가입 | 서버 전용 초기화 절차로 마스터 1개 |
| 세션 쿠키 | 기존 접두사 | `tth-admin` 접두사와 독립 비밀키 |
| 인증 범위 | 플레이·친구·내 정보 | 대시보드·사용자 관리·관리 이력 |

better-auth 라이브러리는 재사용하되 인스턴스·Prisma 모델 매핑·API basePath·쿠키·비밀키를 나눈다. 일반 `User`에 관리자 role을 추가하거나 일반 회원을 승격시키지 않는다. 마스터 자격 증명은 관리자 저장소에서만 검증하고 일반 회원 로그인은 기존 저장소만 사용한다.

### 마스터 계정 운영

- 초기 버전은 운영자용 마스터 계정 1개다. 초기화 명령을 서버에서 한 번 실행해 생성하고, 이미 존재하면 다시 만들거나 비밀번호를 덮어쓰지 않는다.
- 아이디·초기 비밀번호는 운영 시 안전한 서버 입력으로 전달한다. 문서·소스·마이그레이션에 고정 비밀번호를 넣지 않고 비밀번호는 인증 라이브러리 형식의 해시로만 저장한다.
- 관리자 회원가입 API를 비활성화한다. 공개 인증 경로는 로그인·세션 확인·로그아웃에 필요한 경로와 HTTP 메서드만 허용한다. 숨긴 가입 UI만으로 제한하지 않는다.
- 마스터 비활성화·비밀번호 교체·복구는 서버 전용 관리 절차를 쓰고 기존 관리자 세션을 모두 만료시킨다. 공개 초기화·복구 API와 기본 비밀번호는 제공하지 않는다.
- 마스터 로그인 실패에는 요청 빈도 제한을 적용한다. 관리자 인증의 신뢰 출처는 실제 배포 출처만 허용한다.
- 관리자 세션은 최초 로그인부터 최대 8시간, 자동 연장 없이 만료한다. HttpOnly·운영 HTTPS의 Secure 쿠키를 사용하고, 관리자 로그아웃은 관리자 세션·쿠키·캐시만 지운다.

### 접근 경계

1. `requireAdmin`은 `adminAuth`의 세션과 DB의 `AdminUser.disabledAt`을 확인한다. 일반 `getCurrentUser`로 관리자 인증을 대신하지 않는다.
2. 관리자 보호 레이아웃과 각 데이터 서비스·변경 요청에서 검증한다. 세션 쿠키 캐시를 끄고 비활성화·세션 폐기를 다음 요청부터 반영한다.
3. 관리자 세션이 없는 보호 페이지 접근은 `/admin/login`으로 안내한다. 일반 회원 세션만 있는 관리자 API 요청도 미인증 401이며, 유효한 관리자 신원에 권한이 없으면 403이다.
4. 관리자 로그인 페이지·로그인 API는 관리자 인증 없이 열 수 있어야 한다. `proxy.ts`가 일반 로그인으로 보내거나 관리자 세션을 요구하는 루프를 만들지 않는다.
5. 일반 세션으로 관리자 API를 호출하거나 관리자 세션으로 일반 사용자 API를 호출해도 상호 인증되지 않는다. 두 세션이 함께 있으면 각 영역은 자신의 세션만 읽는다.
6. 관리자 응답은 공유 캐시·정적 페이지에 남기지 않는다. 조회·검색·상세 API 모두 필요한 필드만 반환한다. 동일 Next.js 배포 안의 인증 분리이며, 별도 실행 환경의 격리까지 의미하지 않는다.

### 정지·해제·세션 만료

- 정지는 탈퇴와 별도 상태다. `deletedAt`을 제재 용도로 재사용하지 않는다.
- 정지 시 상태 변경·세션 제거·푸시 토큰 제거·감사 이력을 하나의 DB 트랜잭션으로 기록한다. 정지 해제는 계정 상태만 복구하고 로그인·푸시 등록은 다시 진행하게 한다.
- 정지 계정은 로그인 시 거절하고, 살아 있던 세션의 다음 요청도 거절한다. `getCurrentUser`와 로그인 경로 모두에 적용해야 한다. 현재 탈퇴 계정도 로그인 세션 발급 후 앱에서 차단되는 공백이 있으므로 함께 다룬다.
- 친구 검색·레이스·랭킹·신호와 푸시 발송·자동 정산 등 백그라운드 작업에도 정지 조건을 적용한다. 기존 `ACTIVE_USER` 조건을 일관되게 확장하며 과거 통계 쿼리에는 그대로 적용하지 않는다.
- 서버가 조치 직전에 마스터와 대상 일반 회원의 최신 상태를 다시 확인한다. 조치 대상은 `User` 테이블로 한정하고, 동시 상태 변경에도 조치와 감사 이력이 일치하도록 트랜잭션에서 검증한다.
- 모든 기기 로그아웃은 대상 세션만 만료시킨다. 이후 정상 재로그인은 가능하며 계정 정지와 구별한다.
- 조치자는 `AdminUser.id`, 대상은 `User.id`로 구분해 종류·사유·직전/직후 상태·서버 시각을 감사 이력에 남긴다. 비밀번호·토큰 원문을 이력에 기록하지 않는다.

## 7. 추가할 데이터와 수집 방식 — 제안

실제 구현 시 **`docs/data-model.md` 수정 → Prisma 스키마 수정 → `pnpm db:migrate`** 순서로 진행한다. 아래는 신규 모델의 책임을 정한 초안이며 현재 DB 계약이 아니다.

| 변경 | 핵심 필드·책임 | 필요한 시점 |
| --- | --- | --- |
| 관리자 전용 인증 모델 4개 | `AdminUser`의 마스터 신원·`disabledAt`, `AdminAccount`의 비밀번호 해시, `AdminSession`의 세션, `AdminVerification`의 라이브러리 계약 | 마스터 로그인. better-auth 필드 계약과 username 플러그인 계약 유지 |
| `User` 확장 | `suspendedAt`, `suspensionReason`, `analyticsExcluded`. 관리자 role 없음 | 일반 회원 관리 |
| `AdminAuditLog` | `actorAdminId` → AdminUser, `targetUserId` → User, action, reason, before/after의 허용 필드, createdAt | 최초 관리자 조치부터 |
| `UserDailyActivity` | userId + activityDate(KST) unique, firstSeenAt, lastSeenAt | 방문·재방문 계측 |
| `ProductEvent` | 서버 확인 eventId unique, userId, type, occurredAt, 관련 엔티티 ID·상대 사용자 ID | 친구 연결 이력·결과 열람 |

`UserDailyActivity`는 기본적으로 1인 1일 한 행이다. 사용자별 기록 조회용 `(userId, activityDate)`와 날짜별 분석용 `(activityDate, userId)` 인덱스를 검토한다. `ProductEvent`는 `(type, occurredAt)`·`(userId, occurredAt)`, 관리 이력은 `(targetUserId, createdAt)`를 기준으로 조회한다. 정확한 DDL과 삭제 정책은 구현 스펙에서 확정한다.

### 방문 수집

- 인증된 일반 앱 레이아웃에서 최초 전경 표시·전경 복귀·전경 상태의 KST 날짜 변경을 관측한다. `/admin`, `/dev`, 로그인·가입 화면은 제외한다.
- 브라우저가 visible이고 온라인일 때만 `POST /api/activity`를 보낸다. 사용자 ID·권한·수집 시각·KST 날짜는 서버가 결정한다. 클라이언트가 보낸 사용자 ID와 날짜를 저장 근거로 쓰지 않는다.
- 같은 날짜·사용자는 최초 저장 뒤 최대 5분에 한 번만 최근 시각을 갱신한다. 탭 전환과 여러 기기의 중복은 DB unique 조건·원자적 upsert로 합친다.
- 새 날짜에는 5분 제한과 무관하게 즉시 새 행을 만들고, 계정이 바뀌면 클라이언트의 수집 제한 상태를 초기화한다.
- 레이스의 `recordTaps` 성공 경로에서도 일별 활동 행을 보장한다. 방문 수집 요청이 실패한 플레이어가 방문 집계에서 빠지는 일을 줄인다. 같은 날 이미 기록됐다면 매 탭 배치마다 갱신하지 않는다.
- 실패는 플레이를 막지 않는다. 다음 전경 진입·허용된 재시도에서 재전송하되 과거 방문을 임의 날짜로 소급하지 않는다. 화면에는 `서버가 관측한 방문`임과 수집 시작일을 명시한다.
- 최근 방문은 최대 5분 단위로 갱신되는 관측값이다. 이를 초 단위 실시간 온라인 상태로 표시하지 않는다.

### 행동 이벤트

- 친구 요청 생성·수락·거절·취소·삭제·차단을 성공한 도메인 변경과 같은 트랜잭션에서 기록한다. 행위자와 상대 ID를 함께 남겨 수락한 양쪽의 연결을 분석한다. 현재 관계를 덮어써도 이벤트는 남는다.
- 결과 상세를 실제 열었을 때 `result_viewed`를 사용자·결과당 최초 한 번 기록한다. 기존 `seenAt`은 알림 제어용으로 유지한다. 다이얼로그 닫기와 상세 열람을 구별한다.
- 계정 가입·탭·칭호 획득은 기존 DB가 원본이다. 같은 사실을 클라이언트 이벤트로 다시 중복 수집하지 않는다.
- 방문·이벤트 수집일 이전 구간은 채워 넣지 않는다. 과거 플레이 D1/D7을 제공한다면 `탭 기준 재참여`라는 별도 이름을 쓴다.
- 1차 버전은 일별 활동 원본과 필요한 도메인 이벤트만 저장한다. 초 단위 heartbeat·체류 시간·페이지 이동 전체·별도 분석 웨어하우스는 추가하지 않는다.

## 8. React·Next.js 구성 제안

```text
src/app/(admin)/admin/
  layout.tsx                       관리자 공통 외형·전용 Provider
  login/page.tsx                   마스터 로그인, 보호 레이아웃 바깥
  (protected)/
    layout.tsx                     마스터 인증·사이드바·데스크톱 레이아웃
    page.tsx                       전체 현황 (/admin)
    analytics/page.tsx             접속·재방문
    engagement/page.tsx            레이스·소셜
    users/page.tsx                 사용자 목록
    users/[userId]/page.tsx        사용자 상세
    audit/page.tsx                 조치 이력
src/app/api/admin/auth/[...all]/route.ts  관리자 전용 인증 경로 허용 목록
src/app/api/admin/...             보호된 지표·목록·상세·조치 API
src/app/api/activity/route.ts      일반 사용자 방문 수집
src/lib/admin-auth/               전용 서버·클라이언트·requireAdmin
src/features/admin/
  components/                   필터·지표·표·차트·조치 다이얼로그
  server/                       권한·집계·사용자 조회·조치 서비스
  metrics.ts                    지표 ID·단위·기간·결과 타입
src/features/analytics/         방문 수집·도메인 이벤트
```

- `(app)` 레이아웃 밖에 `(admin)`을 둔다. 420px 제한, 하단 탭, 레이스 Realtime 구독, 친구 요청·정산 다이얼로그를 관리자 화면에 물려주지 않는다.
- `/admin/login`은 일반 `(auth)` 레이아웃과 세션 검사도 재사용하지 않는다. 관리자 루트 레이아웃은 인증을 강제하지 않고 `(protected)`에서만 강제한다.
- `adminAuth`는 `basePath: /api/admin/auth`, 전용 Prisma 모델 매핑, `ADMIN_AUTH_SECRET`, 전용 cookie prefix를 쓴다. 실제 값은 구현 시 `.env.example`·`deploy.md`·`tech-stack.md`에 추가한다. 일반 인증 설정의 비밀키·회원가입·와일드카드 신뢰 출처를 그대로 복사하지 않는다.
- 서버 데이터는 Prisma와 `@/lib/db`로만 읽는다. 클라이언트가 Supabase 테이블에 직접 접근하는 경로는 만들지 않는다.
- 서버 페이지는 접근 권한을 확인한다. 대시보드 데이터는 TanStack Query → 관리자 Route Handler → 서버 집계 서비스 한 경로로 조회해 서버 페이지와 중복 조회하지 않는다.
- 조회 API: `GET /api/admin/overview`, `/analytics`, `/engagement`, `/users`, `/users/[userId]`, `/audit`. 변경 API: `POST /api/admin/users/[userId]/suspend`, `/unsuspend`, `/revoke-sessions`.
- 변경 요청은 인증·권한 외에도 동일 출처/CSRF 방어, 사유·상태 검증을 적용한다. GET 요청으로 상태를 바꾸지 않는다.
- 날짜·필터는 URL 검색 파라미터에 보관한다. 서버는 최대 90일, 날짜 순서, 페이지 크기와 허용된 정렬 키를 검증한다. 임의 SQL 정렬 문자열을 받지 않는다.
- 조회 결과에 `generatedAt`, `timezone`, `range`, `collectionStartedAt`, 지표별 `value / numerator / denominator / status`를 포함한다. 미수집 값을 0으로 바꾸지 않는다.
- 관리자용 QueryClient와 인증 클라이언트를 별도로 둔다. 쿼리 키에는 `admin`·마스터 ID·기간·필터를 넣고 관리자 로그아웃·401/403에는 진행 중 요청을 취소한 뒤 관리자 캐시만 비운다. 일반 세션과 일반 캐시는 유지한다. 서버 응답은 `private, no-store`, 브라우저 쿼리는 60초 freshness와 수동 새로고침을 기본으로 하고 상시 폴링은 하지 않는다.
- 집계는 DB에서 수행하며 원본 사용자·탭 로그 전체를 브라우저로 보내지 않는다. 초기에는 최대 90일만 집계하고, 필요 시 측정 결과를 바탕으로 일별 집계 테이블을 도입한다.
- 차트만 Client Component로 분리한다. Chart.js의 필요한 차트·축·플러그인을 등록하고 토큰 색상을 적용한다. `ssr: false`가 필요하면 Client Component 안에서 dynamic import를 선언한다.
- 코호트는 의미 있는 HTML 표로 작성한다. 히트맵 하나를 위해 추가 차트 플러그인을 도입하지 않는다.

## 9. 구현 순서와 수용 기준

### 1차 — 관리자 기반과 지금 계산할 수 있는 현황

관리자 전용 로그인·마스터 계정 초기화·독립 세션, 전체 사용자 목록과 상세, 정지·해제·세션 만료·감사 이력, 신규 가입·플레이 DAU·완주·구간·정산 누락을 구현한다. 방문 계측도 함께 시작한다. 접속 지표가 준비되지 않은 화면에는 `수집 중`을 보여준다.

### 2차 — 방문과 재방문 분석

방문 DAU와 플레이 참여율, 가입 활성화, 완성된 관찰 구간의 D1·D7을 연동한다. 7일·30일 수집이 쌓이면 WAU·MAU와 DAU/MAU를 표시한다. 수집 이전 데이터는 복원한 것처럼 제시하지 않는다.

### 3차 — 소셜·보상 개선 판단

친구 행동 이벤트와 실제 결과 열람을 수집하고, 가입 24시간 내 친구 연결별 D7과 신호·칭호 이용을 비교한다. 처음에는 수동 해석으로 운영하고, 데이터가 부족한 상태에서 자동 개발 우선순위를 산출하지 않는다.

### 검증 항목

- 일반 회원 세션만으로 `/admin`을 열면 `/admin/login`으로 이동하고, 보호된 관리자 API·변경 요청은 401이다. 미로그인 상태에서 `/admin/login`이 정상 렌더되며 리다이렉트 루프가 없다.
- 관리자 세션만으로 일반 사용자 API를 호출해도 인증되지 않는다. 동일한 아이디 문자열을 양쪽 저장소에 두어도 서로의 비밀번호·세션을 인정하지 않는다.
- 일반·관리자 세션을 함께 만든 뒤 어느 한쪽에서 로그아웃해도 다른 쪽 세션이 유지된다. 관리자 로그아웃 후 관리자 요청·캐시·뒤로 가기에서 보호 데이터가 다시 표시되지 않는다.
- 마스터 비활성화·비밀번호 교체·관리자 세션 폐기 후 기존 세션의 다음 요청도 차단한다. 일반 사용자 조치 API에 마스터 ID를 넣어도 마스터 인증 테이블에 쓰기가 발생하지 않는다.
- 공개 관리자 회원가입·초기화·복구 요청을 차단한다. 초기화 명령을 다시 실행해도 마스터 중복 생성·비밀번호 덮어쓰기가 없다. 마스터 계정은 회원 수·친구 검색·랭킹·접속 통계에 나타나지 않는다.
- 제재 성공·실패 시 계정 상태·세션·감사 이력의 트랜잭션 일관성을 확인한다. 정지 계정의 친구 검색·랭킹·신호·푸시·정산 경로도 검증한다.
- KST 자정, 여러 탭·기기, 새로고침 반복, 계정 전환에서 방문자가 중복 집계되지 않는다. 숨김 상태와 관리자 화면만 연 경우 방문을 만들지 않는다.
- DAU 합계와 WAU/MAU를 구별하고, 분모 0·미수집·미완료 코호트·기간 경계·탈퇴 후 과거 집계 유지 사례를 검증한다.
- 배치 탭 합계, 한 사람의 여러 플레이일, 정확히 10,000회 완주, 1,500/3,200/5,000/7,300 구간 경계를 검증한다.
- 관리자 상세 조회가 사용자 결과를 읽음 처리하거나 방문을 기록하는 등 제품 상태를 바꾸지 않는다. 관리용 조회 서비스는 일반 사용자 화면의 쓰기 부작용을 재사용하지 않는다.
- 키보드만으로 필터·표·사용자 조치가 가능하고, 차트의 정보는 데이터 표에서도 읽힌다. 390px·768px·1,440px에서 레이아웃을 확인한다.
- 기능 구현 완료 시 `pnpm typecheck`, `pnpm lint`, `pnpm test`를 통과한다. 스키마 변경은 `pnpm db:migrate`가 생성한 마이그레이션을 포함한다.
